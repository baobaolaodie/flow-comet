# KNOWN-ISSUES（归档遗留清单模板）

> 用途：归档节点使用——REVIEW.md 发现区标记为 `[转待办]` 的 Minor 发现 + 已知限制 → 归档时生成 KNOWN-ISSUES.md 置于 `.specs/archive/<日期>-<change-id>/` 下（归档输出 Schema 的可选产物）。
> 用法：按实际 change 修订本模板；「遗留清单」节记录本 change 结束后仍需跟进的事项，每项标注跟进动作与责任批次。
> 纪律：本模板为分发产物——零过程代号；归档实例（.specs/archive/ 下）不受此限。

## 遗留清单

- **版本中间态**：版本 1.3.1 + 113 场景数（发布 1.4.0 时同步版本号与场景数全库变体）
- **初始化检测相关文档既有过程用语**：`reference/init-detection.md` 等含历史过程用语（历史遗留，待清理批次处理；本地代号检查工具的检出层会持续列出，清理后该层转硬性）
- **迭代观察记录问题 1·4（观察级）**：本轮验证过程中记录，未达修复优先级——后续迭代按需复查
- **本地文档健康检查工具版本映射**：`scripts/check-docs-local.mjs` 的版本/场景数一致性子检查用发布时快照，开发窗口期（版本未发布、场景数已增）会误报——由系统测试集的结构检查放行逻辑覆盖，权威判定在引擎自测
- **design 节点 required 自指核验结论**：设计如此，无需修复——详见 `reference/TEST-MATRIX.md` 附节（三模式对照与理由）

## 使用说明

- **归档时**：把 REVIEW.md 发现区 `[转待办]` 的 Minor 条目与已知限制汇总为本清单；无遗留则写「无」
- **跟进**：下一 change 或维护批次按清单逐项处置，处置后移除条目并注明处置结果
- **验证**：归档流程的完整链路（遗留清单 + 目录移动 + 完成态）由系统测试集 H 面覆盖
