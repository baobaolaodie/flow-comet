# Changelog

## [Unreleased]

## [1.7.0] - 2026-11-05

### Added

- **The engine can point at what a task summary is still missing, before the node closes**: `workflow-guard.mjs exit <node> --preflight` runs only the structural gates — declared artifacts present, summary key sections, template skeleton, intake skeleton — never writes state or the hint ledger, and refuses to be combined with `--apply`. Artifacts that only the archive step produces are reported as "generated when archiving runs" rather than required at this point. The per-task checklist in both executor books and the two runtime hints now point at it, while a full `exit` (without `--apply`) stays the end-of-node rehearsal. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **Wave declarations are now read as a projection of dependency levels**: a task's wave must be one past the latest wave among its dependencies (no dependency = wave 1) and tasks sharing a wave must not depend on each other — a declaration that disagrees blocks a new change at the plan exit, naming each task with its dependencies, the wave it declares and the wave it should reach, and offering the two ways out (move it to that wave, or declare the dependency that explains the order); an older change only warns, a plan with no wave section at all says the rule was not checked, a section that is present but yields no line naming a real task is judged like a disagreement rather than skipped, and a controlled replan runs the same judgement. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **Acceptance criteria are checked against the test matrix**: every criterion in the requirement document must appear in TEST.md's 1.1 test matrix — the ones that do not block a new change at the verify exit, with the row to add, while an older change only warns; the review exit prints a single summary line and keeps its exit code. What cannot be read is reported by cause: **only the template missing** (the section names cannot be derived) is reported as not checked with the exit code untouched, while **a carrier document of the change itself missing (`REQUIREMENT.md` / `TEST.md`)**, together with a deleted acceptance section, an acceptance section with no numbered criteria, or a first-round section with no 1.1 matrix at all, is content the engine cannot judge: a new change is blocked instead of guessing, and an older change only warns and counts that warning — deleting the carrier file is no longer a way to say "nothing to judge". **A sample row inside a fenced code block counts as neither coverage nor a declaration**: the matrix section steps over fences, and a sample stays a sample. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A task the wave section never mentions is now named as undeclared**: the check used to compare only the tasks it could resolve in the section, so a plan that declared one wave and left two tasks out of it passed in silence; the task set is now compared both ways, every task that appears on no wave line is listed as undeclared together with the wave it should reach, and the way out is to write it into that wave's line. A fix task — one carrying the fix prefix, or one inside the fix section — keeps its own lifecycle and stays outside that obligation. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **Tasks that could run side by side now have to say so**: two tasks in the same wave, with no dependency path between them and write surfaces that do not overlap, can run together, yet the engine routes them one after the other whenever either of them is unmarked — so a plan leaving either unmarked blocks a new change at the plan exit — the pair is named with the wave they share and which of them is unmarked, and both ways out are printed: mark both parallel (and the wave line `[P]`) so they really run together, or add the dependency that puts them in different waves and makes the order explicit. One marker alone does not count, routing reads the task block rather than the wave line, an older change is warned, and fix tasks are outside the pair rule. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A controlled `replan` runs the TASK section-shape gate before it re-signs**: when the task set is revised during execution, `TASK.md` is checked against the template skeleton (section order, missing sections, empty bodies, structural subsections) and a deleted carrier section counts as missing — so a new change is blocked with the state left byte-identical and no pre-replan backup taken, while an older change is only warned. The gate is the same skeleton judgement the plan exit and `exit --preflight` apply (`replan` never exempts itself), the report names the section to restore, and the recovery line says to retry `replan` once it is back. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))

### Changed

- **`status`, `next` and `record` name the same node**: `status` reports `routeNode` plus a `ROUTE:` line (derived / state / route), `next` prints `WHY:`, and `record` uses the same view — in a fix batch the three agree instead of pointing at a node the guard would reject. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`status.coordinatorMode` follows the routing view** instead of a second derivation, so one response no longer carries two answers for "current node" (observable change in the in-progress state). ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`exit` refuses arguments it does not know**: the argument surface is one node name plus the known flags (`--apply`, `--preflight`, and the global `--protocol <path>`), so an unrecognized `--*` flag, a look-alike flag written with a single dash (`-apply`, `-h`) and any extra positional argument are all usage errors with a non-zero exit instead of being ignored — a typo can no longer look like a preview while the full exit chain runs, and a stray word can no longer be silently dropped. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **The coordinator hint speaks in platform identity channels, and delegation names its order**: the line shared by `entry` and `next` says delegation goes through each platform's identity channel (an isolated worktree is one implementation of the write permission), both executor skill documents state as a hard order that the handoff request must succeed before a subagent is launched, and a successful `replan` prints a line stating that the task-set signature was re-signed. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`record` refuses a malformed evidence payload** instead of storing it: a non-string or empty `summary`, a non-string member of `completedChecks`, or a wrongly typed `lessonsNomination` — the scanned counter included, since the archive exit compares it as a number — now fails immediately with the field path and its actual type, before anything is written; a payload that is not an object at all (a bare string, an array, `null`, a number) is refused the same way instead of being silently rewritten into a summary; previously such a value was stored and only surfaced later, either as a missing-evidence error at the node exit or as a count mismatch when the archive closed. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **A deferral needs a human decision at every severity, and the minor grade is narrowed with a stated reason**: a reviewer can no longer park a finding as deferred on its own authority — the exit asks for the recorded ruling and the escalation that carried it, minor findings included; and a finding may only be graded minor when it changes no behaviour or output, touches no document or message a user reads, adds no second equivalent implementation, weakens no assertion or test discrimination, and involves no cross-platform or distribution shape — otherwise it is graded major, and each minor one states its reason in a fixed line. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`handoff result` checks the return contract before storing it**: a non-object evidence block, a non-string member of `completedChecks` or a non-string commit hash now fails immediately with the field path and its type, while a zero-commit task may still omit the hash. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`handoff request` shows which lessons a task has to answer**: it prints the `LESSONS-HITS` set that the exit would recompute, from the same implementation, so the answers can be written once instead of being discovered at the exit. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`handoff` refuses a contract that is not an object and never borrows a write surface**: a result payload that is not an object (a bare string, an array, `null`, a number) fails at the entry instead of being stored raw, and a task without `<write_files>` no longer inherits the next task's list — on a new change the request blocks instead of being let through to the commit check. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`status` stops naming a node when routing is blocked**: in every state where `next` refuses to advance — a fix batch out of rounds, a stalled fix batch, and a node that looks un-exited it reports no route node and explains why on the `ROUTE` line, `record` no longer claims a next node, and the return path carries a `WHY` line. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **A carrier without the public documents says so**: a package or an installed copy now prints an explicit "not checked" notice instead of reporting its own missing files. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **`handoff result` now requires the matching request**: a result is checked against the recorded delegation before anything is written — a missing request blocks a new change with state left byte-identical and names the request command to run first, an older change only warns, and a zero-commit result or one carrying only the task's own summary is refused the same way, so a result can no longer be recorded ahead of the delegation it reports. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A node's declaration now has to cover the node instead of sampling it**: the exit used to accept any marker of that node as proof that the reading happened, which left the second protocol file of `open` and of `review`, and most of the skills a node requires, with no criterion at all; every protocol file the node reads and every skill its protocol makes mandatory must now be named by a marker of that node, however the markers are spread across `skill-load` calls (one call may carry several `--prompt` flags), and a missing item blocks a new change at the exit with each one named — the protocol file, or the skill together with the marker file it would write — while an older change is warned. A skill the protocol scopes to a delegate is answered by the delegate's return contract, a skill whose requirement depends on the change is required only when that condition holds, and a new change with no marker directory yet is treated as having declared nothing — the exit names each missing protocol file and skill and blocks — while only an older change keeps the gradual warning that the rule is not yet active. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))

### Fixed

- **A summary that marks a section "not applicable" in bold, or adds a reason, is accepted**: the wrapper forms (bold, quote, list, parentheses, backticks) are stripped before the check, `**N/A**（reason）` included, while `**see N/A**` still counts as filled in and is reported. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **Recovery hints print commands you can actually run**: the `record` command is derived per platform, quoted as a whole, and names the shell it works in; the recovery steps come in the order they must run (declare the node's skills first, then record), carry `--protocol` whenever the run did not use the built-in one, and the whole printed command is what the test executes — not a substituted harness path. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **A deleted public mechanism document now fails the documentation check**: the check decides the shape first — a checkout carrying the public documentation map must carry every public document on it, so removing a file is a failure that names it; only a checkout with no public documents at all (an installed skill tree, the npm package) reports a visible skip, and that skip still says the surface was not verified. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **A required artifact declared without paths now says so on both sides**: the preflight used to skip such a declaration while the node exit counted it as missing forever — one declaration, two answers, and one of them an instruction nobody can carry out. Both now block and print the same sentence naming the declaration to fix (add a path, or mark the artifact optional). ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **The delegation gate and `record` share one skill-declaration rule**: `handoff request` no longer accepts a marker found in an archived directory that merely shares this change id (an older, different change) — both gates read the active `.skill-loads/` first and fall back to the single archived declaration directory only when it is absent, so a new change blocks until it declares its own node skill. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **The archive fallback recognizes only this change's own archived directory**: an archived directory is matched by its full `<date>-<change-id>` name instead of by a shared suffix, so a declaration marker in an archived change whose name merely ends with this change id no longer counts as this change's own — a change that has no `.skill-loads/` of its own yet now blocks until it declares its node skill. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **Being archived is decided by this change's own archived directory too**: whether a change counts as archived — an archived historical change is not required to really run its verification commands — now matches the archived directory by its full `<date>-<change-id>` name, so a decoy directory that merely ends with this change id no longer marks this change archived and no longer lets its verification commands be skipped. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **The archive nomination counts only this change's own archived directory**: the archived directory is located by its full `<date>-<change-id>` name, so an archived change that merely shares the suffix is no longer counted, and it can no longer stand in when this change's own archived directory is absent — the report then says there is no directory to count instead of reconciling against someone else's summaries. ([#162](https://github.com/baobaolaodie/flow-comet/pull/162))
- **An out-of-bounds commit report states the fact and names the cause only when it holds**: the report still lists the files outside the task's write surface, and the blocking or warning grade and the exit code are unchanged, but when the delegation record's write surface no longer matches the task's current `write_files` it adds one line saying so and gives the way out — record `request` again before `result` if the plan was changed through replan; if there was no replan, the files really are outside the task's surface and the revert guidance above applies — instead of leaving the executor to read a changed plan as its own mistake and revert work that had become legal; when the two surfaces agree, the report is exactly as before. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A wave section written with full-width punctuation gets the same verdict**: `Wave 1：T01，T02` used to yield a single unusable token, so the check found nothing it could resolve and fell back to not checked, letting through a plan whose half-width twin was refused; the separators now include the full-width comma, semicolon, enumeration mark and colon, so the same plan is judged the same way whichever punctuation it is written in. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A Markdown example inside a section no longer cuts the section short**: where a section body ends is now decided only by its single implementation (`lib/section-body.mjs`) — the outline parsing behind section order, missing sections and empty bodies, and the LESSONS sectioning, all take the same fence-aware scan, so a heading or a horizontal rule pasted inside a fenced sample stays part of the body instead of ending it. The case that mattered most is a review finding quoting Markdown: its entry used to fall out of the findings area and therefore out of the disposition check, and the same truncation could hide wave lines, test-matrix rows and lessons answers written after such a sample. **The scope is stated narrower than before**: what this batch closes is the single source's consumption side and shape side (the shape side now also recognises the line-array cut — `findIndex` + `slice` + a reachable heading test); the few implementations that still locate their own boundaries, because their capability differs or because they sit outside this batch's write surface, are registered one by one in the section-body lock's registry (file + symbol + reason + merge condition), not waved through as "every reader steps over fences". ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **Every declaration command now comes from the protocol instead of being pieced together by hand**: the hint for a template list that does not match, the entry refusal of a protocol file outside the node's own set, the missing marker named by `record`, and the declaration step of the exit recovery all print the same derived form — every protocol file that node reads (the conditional prompt included when it applies), the node's whole template list, and the skill the marker belongs to — so a copied command no longer stops at the next gate; the recovery payload written into the evidence names the required skill as well, and the troubleshooting page's declaration example carries `--templates`, because a new change copying the half command was refused for a missing template declaration. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **The delegation gate now hands back a declaration command you can run**: the refusal printed by `handoff request` used to name a bare script together with a `<skill>` placeholder — a line a shell reads as a redirect — and carried none of the arguments a declaration needs; it now prints the same assembled command the other gates print — the platform's quoted script path, every protocol file the node reads, the node's whole template list, and, when the run did not use the built-in protocol, the protocol it actually resolved — so copying it declares the node's skill and the next `request` passes. When no command can be derived (the protocol cannot be read, or it has no such node), it says so instead of inventing one. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A task's write surface no longer depends on how the element name is capitalized**: `<WRITE_FILES>` and `<write_files>` are the same element, and every check that reads a write surface now takes it from one implementation. A task written with the capitalized tag used to be counted as carrying the field by the check that every task block carries its seven fields, and as having no write surface by the dependency and cross-task checks, so it silently left the judged set — an overlapping same-file parallel pair escaped the write-write check, a test-only parallel task dropped out of the pseudo-parallel warning, and a same-wave pair writing the same file was told to mark itself parallel. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A lesson written inside a fenced sample is no longer an entry to answer**: the lesson book is read through the same fence predicate the section bodies use, so an entry that sits inside a `~~~` block is a writing sample rather than a real entry — it no longer shows up in the hits printed before a delegation or in the set a summary must answer at the exit, while an entry outside the fence is read as before. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A wave section is recognised however its heading is written**: a heading carrying a numbering prefix, a trailing parenthetical or a closing `##` is the same section as the plain one — the check now takes the section name from where the section-shape gate takes it instead of carrying an exact-line pattern of its own, so the spelling of a heading can no longer decide whether the wave rule and the same-wave `[P]` rule run at all; before, any of those forms made the wave check read "no wave section" and report the rule as not checked while the plan passed, although the section-shape gate had found the section all along. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **The recovery lines for a delegation and for `record` can be copied as they stand**: the command now sits on a line of its own with the note on how to run it on a separate line, because a command with its explanation after it is read by the shell as one argument and the evidence payload is rebuilt into something that is not valid JSON; the line printed for a result that arrives without its delegation request also stops showing a bare script name followed by a `<description>` placeholder and prints the whole runnable command — quoted script path and task id included, the description argument optional — so copying either line does what it says. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **A closed ATX heading no longer reads as a missing section**: closing a heading line with `##` is a legal way to write that section, and the acceptance-criteria coverage check and the 1.1 test-matrix section now take it as the section it is — before, the same heading made them report that there was no acceptance section at all and block a new change over it, while a heading pasted inside a fenced sample stays a sample rather than a section. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **The troubleshooting page's declaration example now gives a command for every skill the node requires**: the `open` example showed a single `skill-load` call while `open` requires two, so an example copied as it stood left the next exit naming the skill that had never been declared — the example now prints both commands, on the Chinese page as well. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))
- **The run-root variable now applies to the state and delegation commands as well**: it used to move only the guard side, so an `init` aimed at a scratch directory still wrote the state file in the repository you were standing in — creating the change's branch there too when branch mode is on — replacing the state of the change running there, and `record` / `status` kept reading and writing that same repository; the root is now resolved in one place, so a single call can only mean one directory, and leaving the variable unset keeps today's default of the current directory. ([#163](https://github.com/baobaolaodie/flow-comet/pull/163))

## [1.6.5] - 2026-10-24

### Added

- **Workflow artifacts are now checked against the templates they come from**: each node names the templates it reads, and the exit compares the artifact's heading forms, section order, empty sections and copied-through placeholders against the upstream template plus this repository's registered additions — a first failure points at the template while a repeat names the missing sections, a missing template says so explicitly instead of passing silently, and the project-level documents travel the same path. The recorded baseline follows the new coverage — 350 scenarios and 95 items in the system test suite. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))
- **Two requirements that used to rely on the node books are now checked by the engine**: entering a node prints that node's protocol prompt before the template lines, and `workflow-state.mjs skill-load --prompt` must name the same protocol file — a wrong path is refused rather than recorded silently; every task summary now carries a `## LESSONS 扫描` section beside the `## 自检方法` declaration, that section answering the entries the engine derives from the task's `write_files`, and the archive exit verifies the nomination evidence — how many summaries were scanned, that every nominated entry exists, and a reason when nothing is nominated. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))
- **A frontend design reads one more prompt**: entering the design node for a change whose visual-tone section marks it as frontend prints an additional conditional `READ PROMPT` line pointing at `2a-ui-design.md`, decided by the same structural criterion as the conditional template line and omitted for non-frontend changes. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))

### Changed

- **Breaking: loading a node's skills now declares the templates that node reads**: `workflow-state.mjs skill-load` requires `--templates <a.md,b.md>` for a built-in node with at least one template, and the declared set must match the node's template mapping exactly — missing, extra or misspelled names block a new change while an older change only warns; a node that reads no template (verify / archive) may leave the flag out, and a custom protocol declares the templates of its own nodes. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))
- **Breaking: a lesson written as a level-two heading is now refused at three exits**: entries in the project lesson book must sit inside the entry area as `### L-NNN`, and a `## L-NNN` heading blocks a new change at the open, verify and archive exits — the report prints `file:line → write ### L-NNN` for each offending line, an older change only warns, and numbering and out-of-area checks stay on verify and archive. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))
- **Optional sections may be dropped whole**: a section the template marks as optional can be deleted outright, while a conditional section keeps its heading and may say `N/A` inside — an optional section you keep still has to be filled. ([#159](https://github.com/baobaolaodie/flow-comet/pull/159))

### Fixed

Every tree copy now goes through one portable helper in the shared test layer, with an anchor pinning both the call sites and the helper's single home; the behaviour contract page also states, beside the fallback path, the separate six-dimension declaration the exit requires. ([#157](https://github.com/baobaolaodie/flow-comet/pull/157))

## [1.6.3] - 2026-10-11

A release gathering the work accumulated after 1.6.2: how a delegation is judged is now the same on every supported platform — it rests on the identity the host reports for the caller rather than on how the workspace was built — with the four properties that make parallel work safe written down, every delegation recorded when it is handed off, and the commit and integration discipline written into the node skills; node guidance is read on demand instead of being repeated across the node skills, the facts about a node can be asked for with a read-only command, the pages that are not for the agent's use no longer ship with the installed skill tree, reinstalling no longer leaves generated files behind, and the check that requires every new changelog entry to carry a numbered pull-request link keeps working once a release moves those entries into the version section. ([#145](https://github.com/baobaolaodie/flow-comet/pull/145)) ([#146](https://github.com/baobaolaodie/flow-comet/pull/146)) ([#147](https://github.com/baobaolaodie/flow-comet/pull/147))

### Added

- **Delegation is decided by the caller's identity, on every supported platform**: the guard reads the agent identity the host puts in the payload and applies subagent semantics before it resolves any path, with no platform-specific branch. On Codex this closes a real gap — an interactive session carries the identity for its native subagents, whereas a headless run does not, and it was the headless finding that had been read as a platform limit. A minimal protected set (the state file and the protocol file) stays blocked for subagents, and a write aimed outside the project root is judged the same way whether it arrives as a file edit or as a shell command. ([#145](https://github.com/baobaolaodie/flow-comet/pull/145))
- **A delegation is recorded when it is handed off**: the handoff is written into the execution node's evidence, so the run shows what was delegated. The record states that a delegation happened; it does not prove who executed it, and it is documented that way. ([#145](https://github.com/baobaolaodie/flow-comet/pull/145))
- **Write-conflict checks understand patterns**: a task write-set containing a pattern is matched against the other side's literal paths, and two patterns are treated as overlapping — so a pattern-versus-file overlap can no longer pass the planning exit unnoticed. ([#145](https://github.com/baobaolaodie/flow-comet/pull/145))
- **The full checks wait for a writer to finish**: while a delegated task has been handed off and not yet reported back, running the full verification is refused with recovery guidance instead of measuring a half-written tree; changes created before the rule get a warning. - **Commit and integration discipline are written into the node skills**: subagents commit only their own literal paths, retry when the index is locked and avoid whole-tree commands; the coordinator integrates by merge and falls back to a cherry-pick only with a recorded reason. - **Node facts can be asked for instead of copied into every book**: a read-only command, `workflow-state.mjs explain <node>`, prints the output schema of one node together with its artifact paths and evidence id, its guardrails, the skills that node must load, and its entry, exit and record commands. ### Changed

- **Parallel delegation is defined by four attributes instead of one shape**: the contract is write permission, commit isolation, verification isolation and integration discipline; an isolated worktree implements the first of them and is no longer a precondition for delegating work. ### Fixed

A release gathering the batches accumulated after 1.5.1: the installer no longer borrows the host repository's tags for the version it reports and its messages use the tool's own name; the repository's maintenance documents were rebuilt and cleaned up; repairs reported after review now run through the execution lifecycle, return audit lines state their source explicitly, controlled repair cycles are counted per change with a fourth one pausing for a decision, and task-set signatures record the algorithm that produced them; and an archived change can be re-opened through a controlled, explicitly authorized path. ### Added

- **An archived change can be re-opened through a controlled, explicitly authorized path**: when a defect surfaces only after the change has been archived and before its workspace directory is moved away, the coordinator can return the work to the execution family, review or verify with one command. Each call requires an explicit authorization and a reason, takes a verifiable state snapshot before anything is moved, and records a dedicated audit entry and line that are distinguishable from an ordinary repair reposition or multi-pass finish. A change may use the path up to three times; a further attempt is blocked with continue/stop guidance, and continuing past the cap requires its own explicit authorization for the coming round. Unauthorized calls, out-of-range targets, a moved or already-completed archive are rejected with the state file byte-for-byte unchanged — including on a legacy change, whose shape must not become an authorization bypass, while legacy changes keep their warn-and-proceed behaviour everywhere else.

### Changed
- **The shipped regression suite no longer crashes in projects whose path contains non-ASCII characters**: its installed-copy fixture copied the skill tree with the platform recursive copy, which on Windows ends the process silently when the source path contains characters outside ASCII — in such a project the suite could not get past its two hundredth scenario (reproduced twice in a project whose path contains Chinese characters, while the ASCII-path control run of the same code passed). The fixture now copies directory by directory and file by file, and an anchor copies a tree through a non-ASCII source path and checks the result is complete.

- **Delegation requests are checked against the task's declared execution mode at request time**: a pending task is now rejected unless the workflow is already on the node its declaration expects — the delegation node for a parallel task, the execution node for a serial one. The check runs before any handoff evidence is written, so a rejection leaves the state file byte-for-byte unchanged and records nothing; the message points to `workflow-state next` and then `entry <target node>` for recovery. A correct node that has not been entered only warns, completed tasks and explicit `--write-files` requests are not gated, a protocol without the expected enabled node skips the check, and a legacy change keeps the previous warn-and-proceed behaviour.
- **Controlled repair cycles are counted per change and the fourth one pauses for a decision**: a reposition from the review or verify node back into the execution node with pending repair work now increments a per-change counter; the first three rounds print the round in the audit line, while a fourth reposition on a new change is blocked without moving the workflow and offers "continue repairing / stop" guidance. Continuing requires an explicit user authorization recorded in the handoff evidence; a legacy change warns and proceeds. Failed verify commands use a separate per-change counter, a passing verify does not clear the repair counter, and repositions that are not this controlled form — an already-complete task set, a classification-only pass, or a verify command failure — are not counted.
- **Task-set signatures carry the algorithm version that produced them**: the recorded signature value is prefixed with its version and the applied-exit event also records the algorithm version, so a bare digest written by an older state is read with the original version's semantics. Return classification, controlled reposition and the task-set comparison only compare signatures produced by the same version, so an engine upgrade no longer misreads an ordinary multi-pass finish as an unclosed repair cycle or blocks an unchanged task set; changing the algorithm itself requires an explicit decision at the frozen regression anchor instead of silently reclassifying existing states.
- **A claimed zero-commit handoff is re-verified when the result is recorded**: a result that declares no commit must still prove at result time that its declared outputs are empty or literally ignored. If ignore rules changed, a declared path became tracked, or any existing ancestor segment is a symbolic link or junction, the recorded no-commit flag is withdrawn and the result is rejected on a new change (warned on a legacy one) instead of being exempted from the missing commit hash; the project root is realpath-normalized before the check, and anything that cannot be proven to belong to the zero-commit class still runs the full commit-subset validation. The check is a path-safety proof at decision time: unreferenced commits, a HEAD moved afterwards, races between validation and recording, and commits invisible to a worktree-isolated flow remain documented residual risk, not closed guarantees.
- **Task summaries are checked against the full template skeleton**: every section of the SUMMARY template must now exist — conditional sections may be present with an explicit N/A — and the sections that appear must follow template order, with the mandatory self-check method section placed after the boundary check (at the end or immediately after it). A new change missing a section is blocked with guidance to add it as N/A; a legacy change keeps the progressive warning, and a missing template falls back to the built-in skeleton.
- **The installer's messages use the tool's name**: the output prefix came from the script's own file name, so a command typed as `fcomet` reported every step under a name the user never used — and the usage line in the same output already said `fcomet init`, leaving one command with two names on one screen. The prefix is now `flow-comet`, which matches the tool however it is invoked (the packaged command, its alias, or the script in a repository clone).
- **The orchestration instructions installed into projects no longer carry stale wording or a non-entry**: the opening line described a "bundle" and a "portable control plane" — vocabulary this project dropped when it moved away from its predecessor's layout — and the script list included a two-line compatibility shim that is not an entry point to anything. The opening line now says plainly what the file is, and the shim is no longer advertised. A check keeps that text, which every project loads automatically, free of both.
- **The regression suite now checks the maintenance documents**: the self-test suite validates that references in the maintenance documents resolve and that the roadmap keeps its four sections (it skips where those documents are absent, as in a CI checkout), so drift that CI structurally cannot see is caught locally. The regression suite now runs 267 scenarios and the system test suite 82 items.
- **The documentation now matches the shipped behaviour**: the install guide no longer points at a retired state file or command; the npm channel is described as published; the release checklist includes the npm publish and GitHub Release steps; the Codex section describes serial delivery instead of manual worktree delegation; the force-push rule states its scope; and the Comet badge now carries a boundary note (the two projects no longer share files).
- **Repair batches now run through the execution lifecycle**: when the review or verify node reports defects, the follow-up work is routed back into the execution node and the reposition is recorded in the workflow state, so that node's four exit gates are actually evaluated — every task complete, every task summary present, the self-review evidence declared, and the task set unchanged since entry. Once the repairs pass, the workflow returns to the node that reported the defects and runs that node's own exit gate before continuing, instead of skipping it because its report already exists.
- **Repair-return audit lines are distinguishable again**: when a repair cycle re-enters the execution family and then returns control to the node that reported the defects, the printed line is classified by cause — a genuine repair batch keeps the dedicated repair label, while an ordinary multi-pass close-out prints a neutral return line instead of borrowing that label; a state without enough recorded evidence to tell the two apart prints the neutral line marked unclassified rather than guessing, and the line that keeps a source node in place so its own exit can run is always neutral. Routing, completed nodes and state writes are unchanged; only the audit text differs.
- **A delivery whose declared outputs are empty or all ignored can close without a commit**: a delegated task whose declared outputs are empty, or every one of them is covered by the repository's ignore rules, can now be handed off legally with no commit — the result may omit a commit hash and no handoff error is produced. Anything that cannot be proven to belong to that class still runs the full commit-subset check, and a result that claims no commit without that proof is rejected on a new change (warned on a legacy one), so the accepted form does not open a way around that check.
- **Checks that cannot apply on an installed copy say so explicitly**: the loader version-stamp check that only the authoritative source tree can run now reports "not applicable" when the suite runs from an installed copy, instead of returning silently and being counted as passed; the runner asserts a machine-readable outcome marker on both sides, so a missing or mismatched marker fails the check rather than slipping through.

### Fixed

- **The version marker no longer borrows the host repository's tags**: when the installer's own directory is not a repository root — the shape you get from a local package install, where the package sits under `node_modules/` — the version lookup walked up to the enclosing repository and reported *its* tag. That wrong value was both the answer to `--version` and the marker written into the project being installed, so an installed project could carry a version that belongs to something else. The lookup now trusts the repository only when the installer's directory is the repository root itself, and falls back to the version shipped inside the package otherwise. It also no longer lets the underlying git probe print its own error when there is no repository at all.
- **A repair batch can no longer be closed out from the reporting node directly**: the old path — staying on the node that reported the defects and exiting it there — is rejected with recovery guidance. It let the repair work skip the execution node's lifecycle entirely, so its four exit gates were never evaluated and produced no error, while the reporting node's own gate could still be skipped because its report already existed; the accepted route is now through the execution node and back through the reporting node's exit gate.

- **dsh bridge loader version stamp aligned with the release version**: the loader's `BRIDGE_VERSION` now matches the release version (and the authoritative `INSTALLED_VERSION`), so the read-only bridge health check reports a version-consistent loader on a freshly installed project instead of version skew; the installer's overwrite reporting and the regression suites read the stamp from the authoritative source instead of a fixed value.
- **Worktree-isolated subagents are no longer misclassified as the coordinator**: the project-root anchoring chain (added in the previous release) resolved to the main repository through the host-provided variable, which sits above the isolated worktree — writes inside `.claude/worktrees/**` were then judged against the coordinator whitelist and blocked, even though a worktree subagent writing source is the intended design. The guard now releases that isolation prefix, with `../` traversal protection; the mechanism notes that previously read "the project hook does not apply to subagents" now state the condition under which that was true.
- **A failing state path now explains itself**: when the protocol's state path points at a file that does not exist, the guard reports the resolved path, detects a state file in the other runtime namespace (suggesting the project may not be migrated yet), and names the exact field to correct — instead of a bare "state does not exist". It still fails closed and never falls back.
- **The runtime state path now has a single source**: the literal was repeated across four scripts and a change to one would not alert the others; it now derives from one exported constant, with the write guard's added import measured at about 1.7 ms per invocation.
- **The Claude Code hook command now uses the POSIX form on every platform**: the installer previously emitted a cmd-style `%CLAUDE_PROJECT_DIR%` reference with backslash paths on Windows, but the host executes hook commands with bash semantics — the variable was never expanded and the backslashes were swallowed as escape characters, so the guard script failed to load on every tool call (the host downgraded the crashing hook to a non-blocking error, leaving writes unintercepted); the installer now emits the braced POSIX form on all platforms, and the regression suite verifies the generated command actually executes under the host's semantics.
- **Migration and installer hardening from external review**: four behaviours were corrected. (a) The worktree-isolation release now applies to writes detected from a Bash command, not only to those judged from a file path — previously the same write was allowed through one route and blocked through the other. (b) A path is treated as absent only when it genuinely does not exist; an access error such as a permission failure now surfaces and aborts instead of being silently read as "no legacy state", which could have left a project's state behind while reporting the migration complete. (c) A state file beginning with a UTF-8 BOM is accepted for validation, matching the runtime reader, while the backup and the migrated file keep the original bytes untouched. (d) The `--purge` confirmation is validated before any write, so a command that is ultimately rejected no longer modifies the target first.
- **The contract checker now covers the shared modules**: `protocol-utils`, `state-schema`, `task-parsing` and `route-node` are part of its required list — a copy missing one of them breaks every guard script at import time, yet the checker previously still reported success.
- **The worktree delegation notes no longer document a bypass**: the guidance that recommended writing through a direct File API to evade the write guard is marked as a withdrawn workaround and must not be used; on platforms without agent isolation the delegation step now requires serial execution instead.
- **Task attributes and CLI checks corrected from external review**: task parsing now accepts single-quoted attribute values (previously such a task was silently read as non-parallel, which skewed routing and skipped the parallel-write overlap check); the contract checker escapes the field name before building its regular expression (previously a field containing a bracket threw an error, and one such as `item[0]` matched unrelated text); `--project` now takes precedence over the working directory and rejects a missing value (previously an explicitly given root was silently ignored); and the context-initialization check matches exact headings instead of substrings (previously a heading variant — or even a mere mention in the body — passed the check and recorded a scan time).
- **The isolation-area release now verifies physical containment**: the release added earlier in this batch matched on the normalized path alone, so a symbolic link or junction inside the worktree that points outside it would still be released — and both judgement paths returned before any later containment check, leaving nothing to catch it. The release now resolves each path component and requires the target's real location to stay inside the intended worktree, deriving the landing point from the nearest existing ancestor when the target does not exist yet; resolution failures are refused rather than released. The check runs only when the prefix matches, so ordinary sessions pay nothing.
- **Context validation ignores headings inside fenced code**: the section check matched `##` lines wherever they appeared, so a file missing a required section could still pass if a code example happened to contain that heading — and the scan time was recorded as if the file were complete. Fenced code blocks are now tracked and excluded before the section set is collected.
